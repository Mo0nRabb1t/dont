# D.O.N.T

> "Do or Not To" —— 一个帮助智能体（Agent）梳理开发类想法、评估"做还是不做"的 Skill。
> 通过由浅入深的多轮提问，逐步确认需求，最后给出建议性结论与实施方案。
> 一句话总结：要不要做？不要就给理由，要就给方法。

[English](./README.md) | 中文

## D.O.N.T 能做什么

当你有一个开发类的想法（网站、App、前端、后端、工具、Skill、Agent……），但还不确定值不值得做、怎么做、需要什么功能时，D.O.N.T 会通过分阶段的多轮对话帮你理清思路，并给出结论。

## 核心理念

**要不要做？不要就给理由，要就给方法。**

- 要不要做：第 4 阶段给出建议性结论（做 / 不做 / 用现成 / 改造），由你最终拍板
- 不要做：给出理由与替代方案
- 要做：给出方法——需求深化、技术路线、约束摘要，按需产出文档

## 适用范围

D.O.N.T 仅用于开发类想法的决策与需求澄清。流程结束（产出结论或文档）后，本 skill 即完成使命；后续实际开发、实施与维护不属于本 skill 范围。

## 核心机制

五阶段渐进式提问：

| 阶段 | 内容 |
| --- | --- |
| 1. 意图理解 | 先分析浅层需求，优化提问后复述确认 |
| 2. 需求分析 | 用 5W2H 补齐未知维度并输出汇总表 |
| 3. 背景调查 | 优先搜索现成方案、同类产品并比对（以 GitHub 为主，含 agent 与 skill），再了解时间、预算、能力、环境限制 |
| 4. 决策定论 | 给出建议性结论与理由，由你最终决定 |
| 5. 需求深化 | 确认要做后深化需求细节，最终交付结论、技术路线、约束摘要与改进建议，并提供 A/B/C 交付选择 |

特点：

- **动态提问**：问题数量根据回答调整，偏多偏细；可随时说"直接给结论"跳过。
- **快捷作答**：问题带编号、选项带字母，可直接回复 `1A 2B 3C`（或 `A1 B2 C3`）一次作答多题。
- **现成方案检索**：以 GitHub 为主、不限平台（含 agent 与 skill），先搜索现成方案（收集最多 5 个候选）并比对输出，再了解你的背景；凑够即停，都没有则放弃。默认直接搜索；若你要求先确认再行动，则先询问。
- **输出**：先给出建议性结论与理由；确认要做后再深化需求，最终交付结论、技术路线、约束摘要与改进建议，并提供 A/B/C 选择（A 只出文档 / B 只要结论 / C 出文档并开工）；选文档时先确认类型（默认需求/开发/流程/其他），保存为 Markdown 文件。
- **语言自适应**：跟随用户输入语言，默认英文。
- **技术程度自适应**：前期提问确认你的技术程度，小白会得到带通俗解释的答案，技术用户直接使用专业术语。
- **用户偏好优先**：你的指示与偏好优先于 skill 的默认规则（例如你要求"先确认再行动"时，会先询问你）。

## 安装

D.O.N.T 遵循通用的 SKILL.md 规范，可被多种智能体使用。将 `dont` 目录放入你的智能体（Agent）的 skills 目录即可，具体路径取决于你所使用的智能体。

Windows：

```powershell
Copy-Item -Recurse dont "<skills目录>"
```

也可以使用目录联接（源目录保留在仓库中，方便后续通过 git 更新）：

```powershell
New-Item -ItemType Junction -Path "<skills目录>\dont" -Target (Join-Path (Get-Location) 'dont')
```

macOS / Linux：

```bash
cp -r dont <skills目录>/
```

## 使用

新开一个对话，直接说：

- "我想做个 AI 宠物养成 App"
- "这个想法要不要做？"
- "帮我梳理一下 XXX 的需求"

部分智能体支持 `$skill` 语法，可显式调用 `$dont`；不支持的智能体直接描述需求即可触发。

## 目录结构

```
dont/
├── SKILL.md                      # 核心工作流（五阶段）
├── agents/
│   └── openai.yaml               # UI 元数据
└── references/
    ├── question-tiers.md         # 各阶段问题清单与退出条件
    ├── search-and-comparison.md  # 搜索规则与对比格式
    ├── decision-guide.md         # 决策标准与输出结构
    ├── improvement-checklist.md  # "如何做得更好"检查清单
    └── requirement-template.md   # 按类型（需求/开发/流程等）的文档模板，需用户确认后输出
```
